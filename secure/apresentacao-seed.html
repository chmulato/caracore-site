CaraCore Seed

Sistema Empresarial de Controle de Licenças

1. Sumário Executivo

O Caracore-Seed é um sistema empresarial de controle de licenças que protege e monetiza o acesso ao Caracore-Hub, nossa plataforma unificada de gestão de marketplaces. O sistema implementa um modelo de negócio Software-as-a-Service (SaaS) com cobrança mensal recorrente por Centro de Distribuição, garantindo que apenas clientes autorizados e em dia com pagamentos tenham acesso às funcionalidades premium.

1.1 Valor de Negócio Imediato

  • Proteção de propriedade intelectual e controle de acesso granular
  • Receita recorrente previsível através de assinaturas mensais
  • Monitoramento em tempo real de uso e atividade dos clientes
  • Escalabilidade para crescimento exponencial da base de clientes
  • Compliance e auditoria completa de todas as operações

2. Contexto de Negócio

2.1 O Problema

O Caracore-Hub é uma solução tecnológica que unifica operações de múltiplos marketplaces (Mercado Livre, Shopee, Amazon) em uma única plataforma. Antes do Caracore-Seed, não havia controle efetivo sobre:

  • Quem estava utilizando o sistema
  • Por quanto tempo cada cliente poderia usar
  • Quantos usuários simultâneos por instalação
  • Volume de operações processadas
  • Garantias de pagamento pelos serviços

2.2 A Solução

O Caracore-Seed implementa um sistema de licenciamento online obrigatório que:

  1. Valida credenciais de cada Centro de Distribuição em tempo real
  2. Monitora uso através de heartbeats automáticos a cada 30 minutos
  3. Controla limites de usuários simultâneos e operações diárias
  4. Bloqueia acesso automaticamente quando licenças expiram
  5. Gera receita recorrente via modelo de assinatura mensal

3. Arquitetura Tecnológica

3.1 Componentes Principais

Caracore-Hub (Aplicação Cliente)

  • Função: Plataforma principal de gestão de marketplaces
  • Tecnologia: Jakarta EE com módulo integrado de validação
  • Localização: Centros de Distribuição dos clientes
  • Dependência: Requer validação de licença para operações críticas

Caracore-Seed (Servidor Central)

  • Função: Autoridade central de licenciamento e controle
  • Tecnologia: Jakarta EE 10, Tomcat 10.1.35, PostgreSQL 15
  • Deployment: Docker Compose com alta disponibilidade
  • Interfaces: REST API + Dashboard Web administrativo

Banco de Dados

  • Engine: PostgreSQL 15 com otimizações para high-throughput
  • Estrutura: Licenças, Clientes, Heartbeats, Auditoria
  • Volume: Projetado para milhões de validações por dia

4. Modelo de Negócio

4.1 Estrutura de Licenciamento

O sistema implementa o modelo "MENSAL_CD_ONLINE" com granularidade de uma licença por Centro de Distribuição (identificado por CNPJ único), cobrança mensal recorrente por CD ativo, e conectividade online obrigatória para operação.

4.3 Controles Técnicos

Conectividade

  • Internet obrigatória para validação em tempo real
  • Tolerância offline máxima: 2 horas (para manutenções)
  • Heartbeat automático a cada 30 minutos
  • Fallback local limitado para emergências

Limites Operacionais

  • Usuários simultâneos por plano contratado
  • Volume de sincronizações diárias com marketplaces
  • Módulos funcionais habilitados
  • Prazo de validade renovável automaticamente

9. Riscos e Mitigações

9.1 Riscos Técnicos

Disponibilidade do Serviço

  • Risco: Queda do sistema impacta todos os clientes
  • Mitigação: Cluster multi-zona, backup automático, failover em < 30 segundos

Segurança de Dados

  • Risco: Vazamento de informações de licenças
  • Mitigação: Criptografia end-to-end, auditoria completa, compliance LGPD

Escalabilidade Técnica

  • Risco: Crescimento exponencial de clientes
  • Mitigação: Arquitetura cloud-native, auto-scaling, microsserviços

9.2 Riscos de Negócio

Concorrência

  • Risco: Entrada de players com soluções similares
  • Mitigação: Inovação contínua, fidelização via integração profunda

Mudanças Regulatórias

  • Risco: Novas leis impactando licenciamento de software
  • Mitigação: Monitoramento regulatório, flexibilidade nos termos

Resistência de Clientes

  • Risco: Rejeição ao modelo de cobrança recorrente
  • Mitigação: Programa de migração gradual, demonstração clara de valor
